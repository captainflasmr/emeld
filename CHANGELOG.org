#+TITLE: Changelog for Emeld

* [0.43.0] - 2026-05-29
** Added
- Inline diff peek: ~TAB~ on a file expands a quick unified diff underneath the row (Magit-style), keeping point in the tree; ~TAB~ again collapses it.  Works in both directory and git mode (the git diff between the two revisions), faced with the standard ~diff-*~ faces.  ~TAB~ on a directory still cycles its subtree.
- Git history stepping reaches the working tree: when the newest commit in the walk is ~HEAD~, pressing ~.~ once past it compares that commit against the working tree (uncommitted changes).  The header line shows ~[hist WT/N]~, so a single walk spans from any commit up to your uncommitted work.
- A revision that points at the current ~HEAD~ is labelled ~HEAD (SHA)~ rather than a bare abbreviated SHA, in the pane headers and the ~[git OLD→NEW]~ header line (HEAD is resolved once per scan and cached).

* [0.42.0] - 2026-05-28
** Added
- ~emeld-git-diff~: compare two git revisions side-by-side as the same hierarchical tree of added, deleted and modified files.  Pick any two revisions (commits, branches, tags) or compare a revision against the working tree or the index/staged content — interactively it defaults to ~HEAD~ vs the working tree.  The scan runs ~git diff --name-status~ asynchronously and reuses the existing tree builder and renderer; the header line shows ~[git OLD→NEW]~ and the revision labels.
- In git mode, file content comes from git rather than disk: ~RET~/~f~ shows a file at its revision (via ~git show~, with the working-tree side opening the on-disk file), ~e~ Ediffs the two revisions of a file, and ~=~/~SPC~ / ~d~ / ~D~ show a ~git diff~.  Renames surface as a deleted old path plus an added new path.  Toggling ~Same~ (~S~) merges identical files by enumerating the left revision with ~git ls-tree~.  Header ~RET~ re-selects a revision and ~W~ swaps the two revisions and re-scans.
- A foldable commit-context block between the revision header and the tree, laid out in two columns aligned to the panes: the left (old) commit under the left header and the right (new) commit under the right.  Folded shows each commit's abbreviated SHA and subject; ~c~ (or ~RET~ on the block) unfolds the author, date+time and full commit message.  Folded by default; the choice persists across rescans within the buffer.
- ~emeld-git-step-history~ (~H~ in the transient): step through history one commit at a time.  Starting from a revision (default ~HEAD~), the buffer shows what each commit changed (its first parent vs the commit); ~,~ moves to the older commit and ~.~ back toward the start (newer).  The root commit is compared against the empty tree (shown as ~∅ (root)~), and the header line shows ~[hist i/N]~.  Walks the first-parent chain up to ~emeld-git-history-limit~ commits.  ~,~/~.~ in any git comparison start a walk anchored at the current commit.
- ~emeld-git-diff~ is reachable from the transient menu (~?~) under "Compare" (~G~) and is autoloaded, so it works as an entry point before any comparison is open.
** Changed
- Copy (~C~), delete (~x~) and subdirectory rescan (~C-u g~) are disabled in git mode (history cannot be written to), reporting a ~user-error~ rather than acting.

* [0.41.0] - 2026-05-28
** Added
- Depth-limited initial scan for very large trees or slow filesystems (SMB/NFS).  A prefix argument to ~emeld-diff~ / ~emeld-diff-dwim~ (~C-u 2 M-x emeld-diff~ = two levels; a bare ~C-u~ = one level) scans only that many directory levels using a fast non-recursive ~diff -q~ per level, then stops and shows the tree — avoiding the deep I/O of a full ~diff -rq~.  Directories below the limit (and one-sided directories) are left unscanned and marked with a dim ~…~; drill into any of them with ~C-u g~ (~emeld-refresh-subdir~), which scans that directory fully.  Plain ~g~ re-runs at the same depth, and the header-line shows ~[depth N]~.
- ~emeld-stop-scan~ (~k~): abort an in-progress scan, keeping whatever has been built so far — useful when a full compare of a huge or slow tree is taking too long.  The async ~diff~ process is killed and the timer-driven tree building (full scan, bounded scan and identical-files merge) bails on the next generation check.
** Changed
- ~emeld--stop-scan~ now bumps ~emeld--scan-generation~, so in-flight timer-driven work (the new bounded scan and the identical-files merge) aborts cleanly when a newer scan starts.

* [0.40.0] - 2026-05-28
** Added
- ~emeld-ediff~ (~e~): Ediff the file at point (left vs right) directly, separate from the ~RET~ action.
- ~emeld-diff-root~ (~D~) and ~emeld-diff-dir~ (~d~): show a recursive unified ~diff~ of the whole comparison root, or of the directory at point, in a ~*Diff*~ buffer — honoring the active filter groups and ~.gitignore~ via ~--exclude~.  Switches are shell-quoted so glob excludes (~--exclude=*.foo~) survive shells like fish that error on unmatched wildcards.
- ~emeld-mark-all~ (~M~): mark all changed files (modified + left-only) — the left→right sync set — in a single key.
- rsync copy backend: ~emeld-copy-method~ (~auto~/~rsync~/~builtin~, default ~auto~), ~emeld-rsync-command~ and ~emeld-rsync-options~.  rsync only transfers the changed parts of a file and recurses efficiently; copies run asynchronously (one node at a time) so Emacs stays responsive, with progress and a final tally in the echo area.
- Exact-mirror copying: ~emeld-copy-mirror~ and ~emeld-toggle-mirror~ (~R~).  When on, rsync directory copies use ~--delete~ so the destination exactly matches the source ("copy left→right" becomes a true mirror rather than a merge); the header-line shows ~[Mirror]~ while enabled.
** Changed
- ~=~/~SPC~ (~emeld-soft-diff~) is now a contextual preview that keeps point in the tree: a directory folds/unfolds, a modified file shows a soft ~diff~, and a new/one-sided/identical file is displayed — all without selecting the other window.  ~RET~ (~emeld-action~) remains the focus-moving action (open/Ediff a file, open/expand a directory).
- ~e~ now runs Ediff and ~=~ runs the soft-diff preview (previously both ran the combined ~RET~ action).
- ~r~ (~emeld-redraw~) now also resets the layout — indentation (~emeld-indent-offset~), pane split (~emeld-column-ratio~) and the compact-tree flag (~emeld-compact-tree~) — to their defaults before redrawing.
- ~g~ is now ~emeld-rescan~: plain ~g~ rescans the whole comparison; ~C-u g~ rescans only the directory at point (formerly the dedicated ~R~ key).
- Keybinding moves: ~D~ diff root, ~d~ diff dir at point, ~x~ delete (was ~D~), ~M~ mark-all changed, ~M-d~ toggle modified visibility, ~z~ toggle compact indentation, ~R~ toggle mirror copy.  ~c~ is now unbound.

* [0.36.0] - 2026-05-27

* [0.35.0] - 2026-05-27
** Changed
- Tree indentation widened by one space per level, applied uniformly to files and directories, so a child's connector hangs one column past the parent's content (~│  └─file~) and reads as hooking into the parent's subtree.  This replaces the 0.34.0 files-only indent, which pushed files one column deeper than directories and made a file that was a sibling of a directory (e.g. ~build.gradle.kts~ next to ~src~) look like it belonged to a different directory.  Files now always align with their sibling directories under the correct parent.

* [0.34.0] - 2026-05-27
** Changed
- Files now hang one column deeper than directories in the tree: a file's branch connector is pushed right so it sits tight against the name (~│  └─RoutingEngine.java~), reading as the file hooking onto its parent directory's subtree.  This replaces the 0.33.0 approach of adding a space after the connector (~├─ file~); directory rows are unchanged.

* [0.33.0] - 2026-05-27
** Changed
- File names now render one column to the right of the tree-line connector (~├─ file~ instead of ~├─file~), so the branch dash reads as a connector hooking into the file the way it does for directories (whose expand toggle and folder icon already provide that gap).  Connector and sibling alignment are unchanged.

* [0.32.0] - 2026-05-27

* [0.31.0] - 2026-05-27
** Changed
- When files are hidden (~F~ off), the header-line now emphasizes it: the ~F~ flag and an explicit ~⚠ files hidden~ note are shown in the ~warning~ face.  A files-less tree shows only directories and can look empty, which could otherwise be mistaken for "no differences".

* [0.30.0] - 2026-05-27
** Changed
- The header-line display state now separates the Meld-style primary filters (~S~ Same / ~M~ Modified / ~N~ New) from the secondary display flags (~F~ / ~T~ / ~s~) with a vertical bar — e.g. ~[SMN │ FTs]~ — so the primary filtering stays visually distinct.

* [0.29.0] - 2026-05-27
** Changed
- The header-line no longer lists the active filter groups (the ~[group]~ tags after the toggle indicators).  Filter groups still apply and are still toggled the same way; review them with ~M-x emeld-list-filter-groups~.

* [0.28.0] - 2026-05-27
** Changed
- Tree building (the initial ~diff -rq~ build and the identical-files ~S~ merge) no longer redraws the whole buffer as it streams in, which was the chief cause of jerkiness on large repositories: each redraw rebuilt the entire visible tree and, once started, ran to completion before Emacs could service input.  By default emeld now updates only the lightweight header-line progress bar during a scan and renders the finished tree once on completion, keeping Emacs fully responsive (scrolling/typing) while a large comparison builds.
** Added
- ~emeld-scan-live-render~ (default nil): set to ~t~ to restore watching the tree grow live during a scan (throttled by ~emeld-render-throttle~ and skipped while input is pending), at some cost to responsiveness on large repositories.

* [0.27.0] - 2026-05-26
** Changed
- Building the identical-files (~S~) tree on large repos is much less jerky.  Intermediate redraws are now skipped while there is pending input, so the merge never blocks scrolling or typing (the header-line progress still updates, and the final tree is always rendered on completion).
** Fixed
- The identical-files merge recomputed its progress with ~(length REMAINING)~ on every chunk — O(n²) over a large repo.  It now tracks progress incrementally, cutting wasted work during the merge.

* [0.26.0] - 2026-05-26
** Fixed
- Toggling Same off now returns to a pure diff view.  Top-level directories that contain only identical files (merged in, and lazily loaded, when Same is toggled on) were kept visible by an unconditional "expose top-level subdirectories" rule; they are now hidden when ~emeld-show-same~ is off, leaving only directories that contain differences.

* [0.25.0] - 2026-05-26
** Changed
- The Files toggle (~F~) moved from the top-level ~File Status~ column into the ~View~ sub-menu, which is now split into two columns: ~Show~ (Files/tree-lines/strikethrough/gitignore toggles) and ~Layout~ (fold, indent, pane-resize).  The ~F~ key binding in ~emeld-mode~ is unchanged.

* [0.24.0] - 2026-05-26
** Changed
- The transient (~?~) is now a two-level hierarchy to reduce clutter.  The top level keeps the Meld-style menus as full columns — ~File Status~, ~Filename~ — plus ~Preset~, and adds a ~Menus~ column whose entries open focused sub-menus: ~v~ View, ~n~ Navigate, ~f~ File, ~m~ Mark (new prefixes ~emeld-dispatch-view~/~-navigate~/~-file~/~-mark~).  ~q~/~C-g~ in a sub-menu returns to the top level.  Direct key bindings in ~emeld-mode~ are unchanged, so the hierarchy is only for discovery.

* [0.23.0] - 2026-05-26
** Added
- ~emeld-refresh-subdir~ (~R~, transient Navigate group): targeted rescan of just the directory at point, merged back into the tree without touching the rest of it — for when you know one subdirectory changed on disk and want to avoid a full ~g~ rescan.  Re-diffs that subtree (handling the dir becoming single-sided or vanishing), preserves its expansion state, and honors filter groups / ~.gitignore~.  If point is on a file, its containing directory is rescanned.

* [0.22.0] - 2026-05-26
** Changed
- Marks are now per-side.  Marking (~m~/~u~) tags the file on the side point is in, and the ~*~ is drawn in that side's column next to the filename rather than once at the start of the whole line.  A node can be marked on the left, the right, or both.  ~emeld-copy~ (~C~) copies each marked node from its marked side to the other (a both-marked node copies left→right); ~emeld-delete~ (~d~) deletes each marked node from every side it is marked on.  Bulk-mark commands (~* m~/~* l~/~* c~) mark the left (source) side.  After marking, point advances to the next node on the same side (snapping to the other side only when that side is empty) instead of jumping back to the left column.

* [0.21.0] - 2026-05-26
** Changed
- ~emeld-delete~ (~d~) now acts on marks: when nodes are marked it deletes every marked node present on the current side (skipping those absent there), mirroring ~emeld-copy~ (~C~).  With no marks it still deletes the node at point.  This makes the mark-then-delete workflow (e.g. ~* l~ then ~d~) possible.

* [0.20.0] - 2026-05-26
** Added
- ~emeld-swap-panes~ (~W~): swap the left and right comparison directories and flip all node paths and side-exclusive diff statuses, with no rescan needed.  Bound to ~W~ in the mode map and the transient Navigate group.

* [0.19.0] - 2026-05-26
** Added
- ~F~ toggle (~emeld-show-files~, default ~t~): hide all regular files to show only the directory hierarchy.
- Buffer placeholder messages: ~Scanning directories, please wait...~ while the async diff is in flight (replaces a blank buffer), and ~No differences detected between directories.~ when the scan completes with no changes.
** Changed
- ~emeld--render~ now conditionally inserts these placeholders into the main buffer instead of rendering an empty tree.  The ~emeld--build-tree-from-diff~ final callback sets the status phase to ~done~ before the final render so the "no differences" message appears correctly.

* [0.18.0] - 2026-05-26
** Changed
- Showing identical files (~S~) is far faster on large trees.  Instead of re-running ~diff -rqs~ (which re-reads and compares every file's content), it now lists the left tree (~emeld-list-command~, ~find~ by default) and treats as identical every left file the initial ~diff -rq~ did not already report as differing or left-only — reusing that content comparison rather than repeating it.  ~emeld-same-files-method~ selects ~list~ (default, fast) or ~diff~ (exact, the old behavior).
- The scan now always runs ~diff -rq~; when ~emeld-show-same~ is on, identical files are merged afterwards by the method above instead of via ~diff -rqs~ up front.
** Fixed
- Rescanning (or first scanning) with ~emeld-show-same~ on no longer appears to hang on large trees.  Identical files were assembled through ~emeld--entries-to-nodes-progressive~, which is roughly O(n²) for tens of thousands of entries (≈58 s for a 20k-file tree); they now use the O(1)-per-file merge instead (≈6 s for the same tree).

* [0.17.0] - 2026-05-26
** Added
- Presets: ~emeld-save-preset~ / ~emeld-load-preset~ / ~emeld-delete-preset~ (transient ~ps~/~pl~/~pd~) save and recall a directory pair via completion.  Stored in ~emeld-presets~ and persisted across sessions through ~savehist~.
- Benchmark log: ~emeld-benchmark-record~ appends timing runs — stamped with machine specs and the emeld git revision — to an Org log (~emeld-benchmark-file~, default ~BENCHMARKS.org~); ~emeld-benchmark-system-info~ inserts the specs at point; ~test/bench.sh~ feeds the same log (~EMELD_BENCH_RECORD~/~SAME~/~FILE~ env vars).
- ~emeld-redraw~ (~r~): re-render the current tree without rescanning — recomputes column width from the window, e.g. after a resize.
- Bulk-mark by status for the marked-copy workflow: ~emeld-mark-modified~ (~* m~), ~emeld-mark-left-only~ (~* l~, created-on-left files), and ~emeld-mark-to-copy~ (~* c~) which marks the whole left→right sync set (modified + left-only) so ~C~ copies everything needed to make the right match the left.  New transient ~Mark~ column (also surfacing ~m~/~u~/~U~).
** Removed
- Default ~C-c~ keybindings (~C-c f~, ~C-c s~, ~C-c l~) — use the transient or bind them yourself.

* [0.15.0] - 2026-05-25
