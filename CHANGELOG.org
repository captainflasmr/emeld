#+TITLE: Changelog for Emeld

* [Unreleased]

* [0.48.0] - 2026-06-12
** Fixed
- Header-line warning notes now use a plain ASCII ~(!)~ marker instead of the ~⚠~ warning sign, which rendered as a missing-glyph box on fonts that lack it (common on Windows).  Affects the ~(!) gitignore~, ~(!) files hidden~ and ~(!) N hidden~ notes; the ~warning~ face still highlights them.
- ~emeld-dired~: copying (~C~) now advances point to the next item afterwards, the way the mark commands do, instead of leaving it at the start of the next line.
** Changed
- ~emeld-delete~ (~x~) no longer rescans the whole comparison on completion.  Like ~emeld-copy~, it now re-classifies only the deleted nodes in place — a file deleted from one side becomes one-sided, and a node now gone from both sides drops out of the tree — recomputes their ancestors and re-renders once, so the view updates without the whole tree flashing.  Falls back to a full rescan only if a node cannot be located.
- The top-level transient (~?~) is tidier: the ~Preset~ and ~Compare~ commands moved out of standalone columns into the ~Menus~ column as their own focused sub-menus — ~p~ (Preset →: ~s~ save / ~l~ load / ~d~ delete) and ~C~ (Compare →: ~G~ git revisions / ~H~ git history step) — joining View/Navigate/File/Mark.

* [0.47.0] - 2026-06-11
** Added
- ~emeld-dired~: a tree-navigable, Dired-like file manager.  ~M-x emeld-dired~ shows the current Dired buffer's directory (or ~default-directory~ elsewhere; a prefix arg, or ~M-x emeld-dired-find~, prompts for a directory) as a single foldable tree — built on the same node model and rendering as the diff view and ~emeld-sidebar~ — and lets you work it like Dired: mark files (~m~), flag for deletion (~d~) and expunge (~x~), unmark (~u~ / ~U~ / ~DEL~ / ~t~), copy (~C~), rename/move (~R~), delete (~D~), and create a directory (~+~) or file (~M-+~).  Operations act on the marked files, or on the file at point when nothing is marked, mirroring Dired.  Unlike the sidebar it takes over its window (like Dired) rather than docking, and is mark/operation oriented rather than following the active file.  Directories fold open and closed (~TAB~), ~RET~/~f~ visit (~o~ in another window), ~^~ re-roots at the parent, ~[~/~]~ collapse/expand all, ~g~ refreshes, and ~h~ toggles dotfiles (shown by default).  Children load lazily per directory, the header line shows live marked/flagged counts, and every operation rebuilds the tree in place while preserving expansion and point.

* [0.46.0] - 2026-06-11
** Fixed
- Marking/navigating down a column no longer jumps to the other side at a one-sided file.  When `emeld-show-strikethrough' is on, moving onto a file that is empty on the current side (its struck-through entry) now keeps point on that column instead of snapping to the side with the file — so you can run down the left column marking every file, including the struck right-only ones (which marks them for deletion in the left→right sync).  With strikethrough off, the empty cell is blank, so the snap-to-file behaviour is kept.
** Added
- ~emeld-hide-at-point~ (~C-k~) / ~emeld-unhide-all~ (~C-u C-k~): temporarily hide the node at point — and, for a directory, its subtree — for this session only.  The hide is remembered buffer-locally and skipped by the renderer; it survives a rescan within the session but is never written to ~.dir-locals.el~ (use ~emeld-add-filter-at-point~ for that).  The header line shows a ~⚠ N hidden~ note while anything is hidden, and ~C-u C-k~ restores everything.  For decluttering a scan you still want intact.
- ~emeld-add-filter-at-point~ (~&~, also in the transient filter column): add the file or directory at point as a filter glob and persist it to the project ~.dir-locals.el~ — no hand-editing.  Prompts for the glob (defaults to the basename; edit to e.g. ~*.log~ or a ~sub/dir~ relative path) and the group (completing over existing names, a new name creates a new active group), writes the updated ~emeld-filter-groups~ to ~.dir-locals.el~ at the left root, activates the group and rescans so the matched files drop out at once.  Lets you progressively, permanently tidy up a fresh directory comparison.
- ~emeld-fold-collapsed-indicator~ / ~emeld-fold-expanded-indicator~: customizable fold toggle shown before a directory name (defaults ~"[+] "~ / ~"[-] "~, the previous hard-coded text).  Like ~emeld-dir-prefix~, set them to icons or triangles (e.g. ~"▸ "~ / ~"▾ "~) to mimic Meld.  Honoured by both the diff view and ~emeld-sidebar~.
- ~emeld-dired-left~ (~A~) and ~emeld-dired-right~ (~B~): quick jump to dired for the left/right side of the node at point — a directory opens dired in it, a file opens dired on its parent with point on the file, and with no node (or no path on that side) the side's comparison root is used.  In git mode the repo-relative path is resolved against the repo's working tree.
** Changed
- ~emeld-copy~ (~C~) is now a two-way sync: "make the other side match the side you marked".  A node marked on the side that has the file is copied across (as before); a node marked on its empty, struck-through side is *deleted* from the other side (to trash) — so a one-sided (orphan) file can be resolved either by copying it over or removing it, without switching to ~emeld-delete~.  Deletions run first and synchronously; the confirmation prompt reports the copy and delete counts separately.  To make the empty side markable, marking a one-sided file now targets the side point is in when its strikethrough is shown (~emeld-show-strikethrough~, the default); with strikethrough off it still snaps to the file side.
- The bulk sync marks ~* c~ (~emeld-mark-to-copy~) and ~* a~ / ~M~ (~emeld-mark-all~) now also include right-only files (marked on the empty left side), so ~C~ performs a full left→right mirror — modified overwritten, left-only created, right-only deleted — rather than copies only.
- ~emeld-copy~ no longer rescans the whole comparison on completion.  Only the touched nodes are re-classified in place (a copy makes a node identical, a deletion drops it) and their ancestors recomputed, then the tree is re-rendered once — so the synced section updates without the whole tree flashing.  Falls back to a full rescan only if a node cannot be located in the tree.
- The Modified-files filter toggle moved from ~M-d~ to ~M~, so the three primary filters now sit on the symmetric ~S~ / ~N~ / ~M~ (Same / New / Modified).  ~emeld-mark-all~ (all changed files), previously on ~M~, moves to ~* a~, joining the ~*~ mark-by-status family (~* m~ / ~* l~ / ~* c~ / ~* a~).
- "Expand only paths to changes" (~emeld-expand-changes~) moved from ~\\~ to ~/~.
- The File transient (~?~ → ~f~) is split into four side-by-side columns — Open, Dired, Diff, Sync — instead of one long list (keys unchanged).
- The header-line filter legend now renders the first letter of each primary filter in bold (~*S*ame~ / ~*N*ew~ / ~*M*odified~) as a hint to the key that toggles it.

* [0.45.0] - 2026-06-11
** Fixed
- Rescanning no longer folds away newly-appeared directories.  After a rescan, expansion state is restored only for directories that already existed when it was captured; directories that have just appeared — e.g. a subtree revealed by toggling ~.gitignore~ respect *off* — keep their default-expanded state, matching a first scan, so the new content is shown rather than silently collapsed.
** Added
- The header line shows a ~⚠ gitignore~ note (warning face) while ~emeld-respect-gitignore~ is on, alongside the existing ~⚠ files hidden~ note.  It appears only when active, flagging that git-ignored files — which can be whole subtrees via ~.gitignore~, ~.git/info/exclude~ or the global excludes — are being dropped from the scan, so the omission is never a surprise.
** Changed
- Keybinding moves: ~g~ now redraws (reset layout + redraw, taking over from ~r~, which is now unbound), ~G~ now rescans (~C-u G~ rescans the directory at point), and ~.gitignore~ respect moved from ~G~ to ~I~ (~emeld-toggle-gitignore~).  This follows the common ~g~=refresh / ~G~=full-rescan convention.
- Header-line legend redesigned.  The primary filters are spelled out in Meld's order — ~Same~ ~New~ ~Modified~ — each with an ASCII ~[x]~/~[ ]~ checkbox (renders correctly on Windows consoles and in terminals without Unicode).  The secondary display flags (Files/Tree-lines/Strikethrough/Gitignore) were dropped from the header to reduce clutter — they remain in the transient (~?~) — and the enclosing brackets around the status group were removed.  The scan-status text (~Scanning…~, ~Building tree…~) now appears only while a scan is in progress; when idle the header shows just the filter legend.
- ~z~ now *cycles* tree density instead of toggling it: compact (default) → extreme → wide → compact.  The new ~extreme~ density collapses each level to a single column regardless of ~emeld-indent-offset~ (~│└file~) for the densest possible tree — especially useful in the narrow ~emeld-sidebar~, where ~z~ is now also bound (~emeld-sidebar-cycle-density~, kept buffer-local to the sidebar).  The boolean ~emeld-compact-tree~ option is replaced by the tri-state ~emeld-tree-density~ symbol (~compact~/~extreme~/~wide~), and ~emeld-toggle-compact-tree~ is now an obsolete alias for ~emeld-cycle-tree-density~.  The header-line flags the active non-default density (e.g. ~[Extreme]~, ~[Wide]~), and ~g~ (~emeld-redraw~) resets it along with the other layout vars.

* [0.44.0] - 2026-06-02
** Fixed
- ~revert-buffer~ (and ~auto-revert~) in an emeld comparison buffer no longer errors with "Wrong number of arguments".  ~emeld-refresh~, which serves as the buffer's ~revert-buffer-function~, now accepts the two arguments ~revert-buffer~ passes it (they are ignored); plain ~g~ / ~M-x emeld-rescan~ are unaffected.
- A file whose name contains " and " (e.g. ~rock and roll.txt~) is no longer mis-parsed from ~diff -rq~ output: the split between the two paths is now anchored on the known right-hand directory prefix rather than a greedy " and ", so such files land at the correct place in the tree.
- An in-flight asynchronous rsync copy (~emeld-copy~) is now cancelled when the scan is stopped or the buffer is killed, instead of being left running with a sentinel pointing at a stale tree.
** Changed
- Layout options are now buffer-local: ~emeld-show-tree-lines~, ~emeld-compact-tree~, ~emeld-indent-offset~ and ~emeld-column-ratio~ are made buffer-local in ~emeld-mode~ alongside the other view toggles.  Tweaking tree-lines, the compact layout, indentation (~>~/~<~) or the column split (~}~/~{~) in one comparison no longer leaks into other emeld buffers or the global defaults.
- Packaging: ~emeld-diff~ is now autoloaded (matching ~emeld-git-diff~, ~emeld-diff-dwim~, ~emeld-load-preset~ and ~emeld-sidebar~), and ~emeld.el~ now declares full package metadata — ~Package-Requires~ (~(emacs "27.1") (transient "0.3.0")~), ~Author~, ~Maintainer~, ~URL~ and ~Package-Version~ — so the package installs cleanly via ~package.el~/MELPA and the external ~transient~ dependency is recorded.
** Performance
- Marking / unmarking a single file (~m~ / ~u~) now rewrites just that line's mark glyph in place instead of re-rendering the whole tree, so holding ~m~ down a large comparison no longer slows quadratically.
- Each render builds every node's relative path incrementally from its parent's, rather than walking up to the root per node, and restoring point after a render jumps straight to the target node (recorded during the render) instead of rescanning the whole buffer line by line.
- The progressive tree builder de-duplicates back-filled files via a hash set instead of a linear ~cl-find-if~ per entry, removing an O(n²) cost for very wide directories.

* [0.43.0] - 2026-05-29
** Added
- ~emeld-sidebar~: a treemacs-style file-tree sidebar.  It docks a dedicated side window (~emeld-sidebar-position~, ~emeld-sidebar-width~) showing a single directory tree rooted at the current file's project (git toplevel → ~project.el~ → the file's directory; a prefix arg prompts for the root), reusing the same node model, expand/collapse and tree rendering as the diff view.  Children load lazily per directory; dotfiles are hidden (toggle with ~h~), and filter groups active by default are honoured.  ~RET~ / ~f~ / ~v~ open a file (or toggle a directory) in the main window, ~TAB~ expands/collapses, ~o~ opens without leaving the sidebar, ~g~ refreshes, ~[~ collapses all, ~.~ reveals the main window's file, ~F~ toggles follow-mode, ~q~ closes it.  ~emeld-sidebar-follow-mode~ (a global minor mode, enabled with the sidebar when ~emeld-sidebar-follow~ is non-nil) reveals and highlights the active file as you switch buffers.
- Inline diff peek: ~TAB~ on a file expands a quick unified diff underneath the row (Magit-style), keeping point in the tree; ~TAB~ again collapses it.  Works in both directory and git mode (the git diff between the two revisions), faced with the standard ~diff-*~ faces.  ~TAB~ on a directory still cycles its subtree.
- Git history stepping reaches the working tree: when the newest commit in the walk is ~HEAD~, pressing ~.~ once past it compares that commit against the working tree (uncommitted changes).  The header line shows ~[hist WT/N]~, so a single walk spans from any commit up to your uncommitted work.
- A revision that points at the current ~HEAD~ is labelled ~HEAD (SHA)~ rather than a bare abbreviated SHA, in the pane headers and the ~[git OLD→NEW]~ header line (HEAD is resolved once per scan and cached).
** Changed
- The package is now split across files instead of one large ~emeld.el~: ~emeld-core.el~ (shared core), ~emeld-git.el~ (git revision comparison + history) and ~emeld-sidebar.el~ (file-tree sidebar), with ~emeld.el~ a thin umbrella that ~require~s them all.  ~(require 'emeld)~ still loads everything, so user configs are unaffected — just keep all the ~.el~ files on the load path.
** Removed
- Internal cleanup: removed dead legacy code left over from before the async ~diff -rq~ scan (a pure-Elisp file-comparison path and a duplicate relative-path helper).  The ~emeld-max-content-size~ defcustom went with it — it had no effect since content comparison moved to external ~diff~.  No user-visible behaviour changes; the byte-compile is now warning-free.

* [0.42.0] - 2026-05-28
** Added
- ~emeld-git-diff~: compare two git revisions side-by-side as the same hierarchical tree of added, deleted and modified files.  Pick any two revisions (commits, branches, tags) or compare a revision against the working tree or the index/staged content — interactively it defaults to ~HEAD~ vs the working tree.  The scan runs ~git diff --name-status~ asynchronously and reuses the existing tree builder and renderer; the header line shows ~[git OLD→NEW]~ and the revision labels.
- In git mode, file content comes from git rather than disk: ~RET~/~f~ shows a file at its revision (via ~git show~, with the working-tree side opening the on-disk file), ~e~ Ediffs the two revisions of a file, and ~=~/~SPC~ / ~d~ / ~D~ show a ~git diff~.  Renames surface as a deleted old path plus an added new path.  Toggling ~Same~ (~S~) merges identical files by enumerating the left revision with ~git ls-tree~.  Header ~RET~ re-selects a revision and ~W~ swaps the two revisions and re-scans.
- A foldable commit-context block between the revision header and the tree, laid out in two columns aligned to the panes: the left (old) commit under the left header and the right (new) commit under the right.  Folded shows each commit's abbreviated SHA and subject; ~c~ (or ~RET~ on the block) unfolds the author, date+time and full commit message.  Folded by default; the choice persists across rescans within the buffer.
- ~emeld-git-step-history~ (~H~ in the transient): step through history one commit at a time.  Starting from a revision (default ~HEAD~), the buffer shows what each commit changed (its first parent vs the commit); ~,~ moves to the older commit and ~.~ back toward the start (newer).  The root commit is compared against the empty tree (shown as ~∅ (root)~), and the header line shows ~[hist i/N]~.  Walks the first-parent chain up to ~emeld-git-history-limit~ commits.  ~,~/~.~ in any git comparison start a walk anchored at the current commit.
- ~emeld-git-diff~ is reachable from the transient menu (~?~) under "Compare" (~G~) and is autoloaded, so it works as an entry point before any comparison is open.
** Changed
- Copy (~C~), delete (~x~) and subdirectory rescan (~C-u g~) are disabled in git mode (history cannot be written to), reporting a ~user-error~ rather than acting.

* [0.41.0] - 2026-05-28
** Added
- Depth-limited initial scan for very large trees or slow filesystems (SMB/NFS).  A prefix argument to ~emeld-diff~ / ~emeld-diff-dwim~ (~C-u 2 M-x emeld-diff~ = two levels; a bare ~C-u~ = one level) scans only that many directory levels using a fast non-recursive ~diff -q~ per level, then stops and shows the tree — avoiding the deep I/O of a full ~diff -rq~.  Directories below the limit (and one-sided directories) are left unscanned and marked with a dim ~…~; drill into any of them with ~C-u g~ (~emeld-refresh-subdir~), which scans that directory fully.  Plain ~g~ re-runs at the same depth, and the header-line shows ~[depth N]~.
- ~emeld-stop-scan~ (~k~): abort an in-progress scan, keeping whatever has been built so far — useful when a full compare of a huge or slow tree is taking too long.  The async ~diff~ process is killed and the timer-driven tree building (full scan, bounded scan and identical-files merge) bails on the next generation check.
** Changed
- ~emeld--stop-scan~ now bumps ~emeld--scan-generation~, so in-flight timer-driven work (the new bounded scan and the identical-files merge) aborts cleanly when a newer scan starts.

* [0.40.0] - 2026-05-28
** Added
- ~emeld-ediff~ (~e~): Ediff the file at point (left vs right) directly, separate from the ~RET~ action.
- ~emeld-diff-root~ (~D~) and ~emeld-diff-dir~ (~d~): show a recursive unified ~diff~ of the whole comparison root, or of the directory at point, in a ~*Diff*~ buffer — honoring the active filter groups and ~.gitignore~ via ~--exclude~.  Switches are shell-quoted so glob excludes (~--exclude=*.foo~) survive shells like fish that error on unmatched wildcards.
- ~emeld-mark-all~ (~M~): mark all changed files (modified + left-only) — the left→right sync set — in a single key.
- rsync copy backend: ~emeld-copy-method~ (~auto~/~rsync~/~builtin~, default ~auto~), ~emeld-rsync-command~ and ~emeld-rsync-options~.  rsync only transfers the changed parts of a file and recurses efficiently; copies run asynchronously (one node at a time) so Emacs stays responsive, with progress and a final tally in the echo area.
- Exact-mirror copying: ~emeld-copy-mirror~ and ~emeld-toggle-mirror~ (~R~).  When on, rsync directory copies use ~--delete~ so the destination exactly matches the source ("copy left→right" becomes a true mirror rather than a merge); the header-line shows ~[Mirror]~ while enabled.
** Changed
- ~=~/~SPC~ (~emeld-soft-diff~) is now a contextual preview that keeps point in the tree: a directory folds/unfolds, a modified file shows a soft ~diff~, and a new/one-sided/identical file is displayed — all without selecting the other window.  ~RET~ (~emeld-action~) remains the focus-moving action (open/Ediff a file, open/expand a directory).
- ~e~ now runs Ediff and ~=~ runs the soft-diff preview (previously both ran the combined ~RET~ action).
- ~r~ (~emeld-redraw~) now also resets the layout — indentation (~emeld-indent-offset~), pane split (~emeld-column-ratio~) and the compact-tree flag (~emeld-compact-tree~) — to their defaults before redrawing.
- ~g~ is now ~emeld-rescan~: plain ~g~ rescans the whole comparison; ~C-u g~ rescans only the directory at point (formerly the dedicated ~R~ key).
- Keybinding moves: ~D~ diff root, ~d~ diff dir at point, ~x~ delete (was ~D~), ~M~ mark-all changed, ~M-d~ toggle modified visibility, ~z~ toggle compact indentation, ~R~ toggle mirror copy.  ~c~ is now unbound.

* [0.28.0] - 2026-05-27
** Changed
- Tree building (the initial ~diff -rq~ build and the identical-files ~S~ merge) no longer redraws the whole buffer as it streams in, which was the chief cause of jerkiness on large repositories: each redraw rebuilt the entire visible tree and, once started, ran to completion before Emacs could service input.  By default emeld now updates only the lightweight header-line progress bar during a scan and renders the finished tree once on completion, keeping Emacs fully responsive (scrolling/typing) while a large comparison builds.
** Added
- ~emeld-scan-live-render~ (default nil): set to ~t~ to restore watching the tree grow live during a scan (throttled by ~emeld-render-throttle~ and skipped while input is pending), at some cost to responsiveness on large repositories.

* [0.27.0] - 2026-05-26
** Changed
- Building the identical-files (~S~) tree on large repos is much less jerky.  Intermediate redraws are now skipped while there is pending input, so the merge never blocks scrolling or typing (the header-line progress still updates, and the final tree is always rendered on completion).
** Fixed
- The identical-files merge recomputed its progress with ~(length REMAINING)~ on every chunk — O(n²) over a large repo.  It now tracks progress incrementally, cutting wasted work during the merge.

* [0.23.0] - 2026-05-26
** Added
- ~emeld-refresh-subdir~ (~R~, transient Navigate group): targeted rescan of just the directory at point, merged back into the tree without touching the rest of it — for when you know one subdirectory changed on disk and want to avoid a full ~g~ rescan.  Re-diffs that subtree (handling the dir becoming single-sided or vanishing), preserves its expansion state, and honors filter groups / ~.gitignore~.  If point is on a file, its containing directory is rescanned.

* [0.22.0] - 2026-05-26
** Changed
- Marks are now per-side.  Marking (~m~/~u~) tags the file on the side point is in, and the ~*~ is drawn in that side's column next to the filename rather than once at the start of the whole line.  A node can be marked on the left, the right, or both.  ~emeld-copy~ (~C~) copies each marked node from its marked side to the other (a both-marked node copies left→right); ~emeld-delete~ (~d~) deletes each marked node from every side it is marked on.  Bulk-mark commands (~* m~/~* l~/~* c~) mark the left (source) side.  After marking, point advances to the next node on the same side (snapping to the other side only when that side is empty) instead of jumping back to the left column.

* [0.21.0] - 2026-05-26
** Changed
- ~emeld-delete~ (~d~) now acts on marks: when nodes are marked it deletes every marked node present on the current side (skipping those absent there), mirroring ~emeld-copy~ (~C~).  With no marks it still deletes the node at point.  This makes the mark-then-delete workflow (e.g. ~* l~ then ~d~) possible.

* [0.20.0] - 2026-05-26
** Added
- ~emeld-swap-panes~ (~W~): swap the left and right comparison directories and flip all node paths and side-exclusive diff statuses, with no rescan needed.  Bound to ~W~ in the mode map and the transient Navigate group.

* [0.19.0] - 2026-05-26

* [0.18.0] - 2026-05-26
** Changed
- Showing identical files (~S~) is far faster on large trees.  Instead of re-running ~diff -rqs~ (which re-reads and compares every file's content), it now lists the left tree (~emeld-list-command~, ~find~ by default) and treats as identical every left file the initial ~diff -rq~ did not already report as differing or left-only — reusing that content comparison rather than repeating it.  ~emeld-same-files-method~ selects ~list~ (default, fast) or ~diff~ (exact, the old behavior).
- The scan now always runs ~diff -rq~; when ~emeld-show-same~ is on, identical files are merged afterwards by the method above instead of via ~diff -rqs~ up front.
** Fixed
- Rescanning (or first scanning) with ~emeld-show-same~ on no longer appears to hang on large trees.  Identical files were assembled through ~emeld--entries-to-nodes-progressive~, which is roughly O(n²) for tens of thousands of entries (≈58 s for a 20k-file tree); they now use the O(1)-per-file merge instead (≈6 s for the same tree).
