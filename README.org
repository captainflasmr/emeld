#+TITLE: Emeld: Meld-Inspired Local Diff
#+AUTHOR: Antigravity

* Introduction

Emeld is a simple, side-by-side directory comparison tool for Emacs. It is designed to be a lightweight and maintainable alternative to other directory diff tools, with a focus on ease of use and a clean hierarchy.

* Features
- Side-by-side view in a single buffer.
- Recursive glob-based filtering (like Meld) — excluded at the ~diff~ level.
- ~.gitignore~ support, on by default — ignored files hidden on both sides, toggle with ~G~.
- Instant toggles for Identical, Modified, New, and File visibility (~S~/~M-d~/~N~/~F~).
- Orphan files shown with strikethrough on the missing side (Meld-style, toggle ~s~).
- Dired-style, per-side marking (~m~/~u~/~U~): the ~*~ sits in the column of the side you mark, and a node can be marked left, right, or both.  Bulk copy (~C~) copies each marked node from its marked side; bulk delete (~x~) deletes from every marked side; mark all changed files (~M~), or bulk-mark by status (~* m~ modified, ~* l~ left-only, ~* c~ the left→right sync set).
- Filter groups toggleable from the transient menu.
- Org-mode-style visibility cycling: ~S-TAB~ cycles the whole tree (TOP → DIRS → CHANGES), ~TAB~ does the equivalent for the subtree at point.
- Bulk expand/collapse: ~[~ collapse all, ~]~ expand all, ~\\~ expand only paths leading to changes.
- File copying between directories (~C~), via rsync when available — asynchronous and delta-efficient, with an optional exact-mirror (~--delete~) mode toggled with ~R~.
- Recursive ~diff~ buffers for the whole root (~D~) or the directory at point (~d~), and a non-intrusive preview (~=~/~SPC~) that diffs/opens the node at point while keeping point in the tree.
- Export changes as a unified-diff patch (~P~).
- Presets: save a directory pair and recall it later for fast repeated comparisons.
- Side-aware navigation (~n~/~p~) and side-jumping (~o~).
- Targeted rescan of just the directory at point (~C-u g~) when one subtree changed on disk, avoiding a full rescan.
- Depth-limited "shallow" scan for huge trees or slow mounts (SMB/NFS): prefix ~emeld-diff~ with a depth (~C-u 2 M-x emeld-diff~) to scan only the top levels and stop; deeper directories are marked with a dim ~…~ and drilled into on demand with ~C-u g~.
- Integration with ~ediff~.
- Fully themeable (uses standard Emacs faces).

* Installation
Copy the files to your load path and add the following to your init file:
#+begin_src elisp
(add-to-list 'load-path "~/.emacs.d/offline-packages/local-packages/emeld")
(require 'emeld)
#+end_src

* Usage
Run ~M-x emeld-diff~ and select the two directories you wish to compare.
Alternatively, run ~M-x emeld-diff-dwim~ to automatically use open Dired buffers as the comparison sources.

For very large trees or slow filesystems (SMB/NFS), give ~emeld-diff~ a prefix argument to limit the initial scan depth — e.g. ~C-u 2 M-x emeld-diff~ scans two directory levels, ~C-u M-x emeld-diff~ just one.  The scan stops there and shows the tree; directories below the limit (and one-sided directories) are marked with a dim ~…~.  Drill into any marked directory with ~C-u g~ (which scans it fully), and plain ~g~ re-runs the bounded scan at the same depth.  The header-line shows ~[depth N]~ while a depth limit is in effect.

** Comparing git revisions

From inside a git work tree, run ~M-x emeld-git-diff~ (or ~G~ in the transient menu) to compare two revisions instead of two directories.  You are prompted for a left (old) and right (new) revision; completion offers branches, tags and recent commits, plus ~[working tree]~ and ~[index]~.  The default compares ~HEAD~ against the working tree, i.e. "what have I changed since the last commit".

The result is the same side-by-side tree, showing the hierarchy of added, deleted and modified files between the two revisions (renames appear as a deleted old path plus an added new path).  Because the content lives in git history rather than on disk:

- ~RET~ / ~f~ opens a file at its revision (via ~git show~; the working-tree side opens the real file), ~e~ Ediffs the two revisions, and ~=~ / ~SPC~ / ~d~ / ~D~ show a ~git diff~.
- ~S~ (show Same) lists the left revision and merges in every unchanged file.
- Header ~RET~ re-selects a revision for that side; ~W~ swaps the two revisions; ~g~ re-scans.
- Copy (~C~), delete (~x~) and subdirectory rescan are disabled — history cannot be written to.

The header line shows ~[git OLD→NEW]~ with the chosen revision labels.

* Transient Menu (~?~)

The transient is a two-level hierarchy.  The top level keeps the menus you reach for most often as full columns, plus a ~Menus~ column whose entries open focused sub-menus.  Pressing ~q~ (or ~C-g~) in a sub-menu returns to the top level.

Top level:

- ~File Status~ :: Toggle file visibility (~S~ same, ~M-d~ modified, ~N~ added).
- ~Filename~ :: Toggle filter groups on/off (~ca~, ~cb~, ... ~[x]~/~[ ]~ checkmarks), ~cl~ list all globs.
- ~Preset~ :: Save the current directory pair (~ps~), load a saved pair (~pl~), delete one (~pd~).
- ~Menus~ :: Open a sub-menu — ~v~ View, ~n~ Navigate, ~f~ File, ~m~ Mark.

Sub-menus (opened from the ~Menus~ column):

- ~View~ (~v~) :: Two columns. ~Show~ toggles what is displayed — files (~F~ hide files, show directories only), tree-lines (~T~), compact indentation (~z~), strikethrough (~s~), ~.gitignore~ respect (~G~). ~Layout~ holds bulk expand/collapse (~[~ collapse all, ~]~ expand all, ~\\~ expand to changes, ~<backtab>~ cycle visibility), indent (~>~/~<~), and pane resize (~{~/~}~).
- ~Navigate~ (~n~) :: Rescan (~g~; ~C-u g~ rescans just the directory at point), stop an in-progress scan (~k~), redraw after a resize (~r~), swap panes (~W~), and jump (~o~ other side, ~M-n~/~M-p~ next/prev change).
- ~File~ (~f~) :: Operate on files (~RET~ smart action, ~e~ ediff, ~=~/~SPC~ preview without leaving the tree — soft diff a modified file, show a new/one-sided one, fold a directory, ~D~ diff whole root, ~d~ diff directory at point, ~C~ copy marked/at point, ~R~ toggle mirror copy, ~x~ delete marked/at point, ~w~ copy path, ~P~ format patch).
- ~Mark~ (~m~) :: Mark/unmark the file on the current side (~m~/~u~); mark all changed files (~M~); bulk-mark by status — modified (~* m~), left-only (~* l~), or the whole left→right sync set (~* c~, same set as ~M~); ~U~ unmark all.

Every command keeps its direct key binding in ~emeld-mode~ (see below), so the menu hierarchy is only for discovery — you never have to drill through it to reach a command you already know.

#+begin_src elisp
(with-eval-after-load 'emeld
  (define-key emeld-mode-map (kbd "C-c f") #'emeld-toggle-filter-group)
  (define-key emeld-mode-map (kbd "C-c s") #'emeld-save-preset)
  (define-key emeld-mode-map (kbd "C-c l") #'emeld-load-preset))

* Customization

- ~emeld-filter-groups~: Named groups of globs toggleable from the transient menu.  Defaults:

  | Group           | Globs                                                                                                       |
  |-----------------+-------------------------------------------------------------------------------------------------------------|
  | Backups         | ~#*#~, ~.#*~, ~~*~, ~*~~, ~*.orig~, ~*.bak~, ~*.swp~                                                        |
  | OS metadata     | ~.DS_Store~, ~._*~, ~.Spotlight-V100~, ~.Trashes~, ~Thumbs.db~, ~Desktop.ini~                               |
  | Version Control | ~.git~, ~.svn~, ~.hg~, ~CVS~, ~_darcs~, ~.bzr~, ~_MTN~, ~.fslckout~, ~_FOSSIL_~, ~.fos~, ~.osc~             |
  | Binaries        | ~*.pyc~, ~*.a~, ~*.obj~, ~*.o~, ~*.so~, ~*.la~, ~*.lib~, ~*.dll~, ~*.exe~                                   |
  | Media           | ~*.jpg~, ~*.gif~, ~*.png~, ~*.bmp~, ~*.wav~, ~*.mp3~, ~*.ogg~, ~*.flac~, ~*.avi~, ~*.mpg~, ~*.xcf~, ~*.xpm~ |

- ~emeld-show-same~: Whether to show identical files (default nil).  When enabled, identical files appear in the tree.
- ~emeld-show-files~: Whether to show regular files (default t).  When disabled, only directories are displayed — isolate the folder hierarchy with ~F~.
- ~emeld-same-files-method~: How toggling ~S~ finds identical files — ~list~ (default, fast: enumerate the left tree and subtract the files the initial scan already classified, avoiding a second content comparison) or ~diff~ (exact: re-run ~diff -rqs~).
- ~emeld-list-command~: Program + args used by the ~list~ method to enumerate files (default ~("find" "." "-type" "f")~; set to e.g. ~("fd" "--type" "f" "--hidden" "--no-ignore")~ to use fd).
- ~emeld-show-strikethrough~: Show strikethrough for orphan files on the missing side (default ~t~).  When nil, the missing side shows nothing.
- ~emeld-respect-gitignore~: Respect ~.gitignore~ rules during comparison (default ~t~).  Ignored files are hidden on both sides via a cached ~git ls-files~ query per root (honors nested ~.gitignore~, ~.git/info/exclude~, and the global excludes file).  Toggle interactively with ~G~.  Requires the ~git~ executable; has no effect outside a work tree.
- ~emeld-compact-tree~: Compact tree indentation (default t).  By default the continuation indent matches the branch width for a tighter tree (~│ └─file~) that sits better in the available space; set to nil for the wider layout, where each level indents one space wider than the branch connector so a child's connector hangs one column past the parent's content (~│  └─file~), reading as hooking into the parent's subtree.  Files align with their sibling directories either way.  Toggle with ~z~.
- ~emeld-dir-prefix~: Unicode prefix for directory names (default ~"📁 "~).
- ~emeld-column-ratio~: Left pane width as percentage of window (default 50).
- ~emeld-scan-live-render~: Whether to redraw the tree progressively while a scan builds it (default nil).  Each redraw rebuilds the whole visible tree and, once started, blocks input until it finishes — the chief cause of jerkiness while a large comparison streams in.  By default emeld instead updates only the lightweight header-line progress bar during a scan and draws the finished tree once on completion, keeping Emacs fully responsive.  Set to ~t~ to watch the tree grow live (throttled by ~emeld-render-throttle~), at some cost to responsiveness on large repositories.
- ~emeld-render-throttle~: Minimum seconds between intermediate buffer redraws during a scan (default 0.15).  Only consulted when ~emeld-scan-live-render~ is non-nil; raise it to redraw less often on very large trees.  Intermediate redraws are also skipped whenever there is pending input, so an in-progress scan never blocks scrolling or typing; the final result is always rendered on completion.
- ~emeld-benchmark~: When non-nil, collect and report phased scan timings (default nil).  Both the initial scan and the identical-files (~S~) merge print a per-stage timing report to the echo area / ~*Messages*~.
- ~emeld-benchmark-file~: Org file where ~emeld-benchmark-record~ appends timing entries (default ~BENCHMARKS.org~ beside ~emeld.el~).
- ~emeld-copy-method~: How ~emeld-copy~ (~C~) transfers files — ~auto~ (default: use rsync when found on ~exec-path~, else the built-in copy), ~rsync~ (always rsync; error up front if missing), or ~builtin~ (always ~copy-file~ / ~copy-directory~).  rsync only sends the changed parts of a file, preserves metadata, and recurses efficiently, so it is faster and more robust for large or partly-synced trees.  rsync copies run *asynchronously* (one node at a time, so Emacs stays responsive; progress and the final tally show in the echo area, output is logged to ~ *emeld-rsync*~); built-in copies are synchronous.
- ~emeld-rsync-command~: Name or absolute path of the rsync executable (default ~"rsync"~).
- ~emeld-rsync-options~: Options passed to rsync, as a list of strings (default ~("-a")~).  ~-a~ preserves permissions, timestamps and symlinks and recurses; add e.g. ~"-z"~ for compression.  ~--delete~ is controlled separately by ~emeld-copy-mirror~, not by this list.
- ~emeld-copy-mirror~: When non-nil, rsync directory copies are exact mirrors via ~--delete~ (default nil) — the destination directory is made to match the source exactly, removing files present only on the destination, so "copy left→right" becomes a true mirror rather than a merge.  Only affects rsync copies of directories (single files and the built-in copy are unaffected, since ~--delete~ has nothing to prune for one file and ~copy-directory~ cannot delete).  To mirror a whole tree, copy a directory node (e.g. a left-only directory) with this enabled.  ~emeld-copy~ labels the action "Mirror" and warns before proceeding.  Toggle it interactively with ~R~ (~emeld-toggle-mirror~); while on, the header line shows ~[Mirror]~.
- ~emeld-presets~: Saved directory pairs as ~(NAME LEFT RIGHT)~, managed by the preset commands (see below) and persisted across sessions via ~savehist~.

* Presets

Frequently-compared directory pairs can be saved and recalled:

- ~M-x emeld-save-preset~ (or ~ps~ in the transient) — name and save the current comparison's left/right directories.
- ~M-x emeld-load-preset~ (or ~pl~) — pick a saved pair via completion (annotated with its directories) and start the comparison.  This is autoloaded, so it works as an entry point even before any comparison is open.
- ~M-x emeld-delete-preset~ (~pd~) — remove a saved pair.

Presets are stored in ~emeld-presets~, which emeld registers with ~savehist-additional-variables~.  With ~savehist-mode~ enabled they persist across sessions automatically; without it they last only for the current session.

* Benchmarking and Regression Tracking

To keep a record of large-repo comparison timings across builds:

1. Enable timing collection: ~(setq emeld-benchmark t)~.
2. Run one or more comparisons (the initial scan, and toggle ~S~ for the identical-files pass).  Each completed scan prints a report and is queued in memory.
3. ~M-x emeld-benchmark-record~ writes all queued runs to ~emeld-benchmark-file~ under a single dated heading, stamped with the machine specs and emeld git revision, then clears the queue.

Because every entry records the host, CPU, RAM, Emacs version and emeld build, the resulting ~BENCHMARKS.org~ lets you compare runs across commits and machines to spot performance regressions.  ~M-x emeld-benchmark-system-info~ inserts the current machine's specs at point if you want to annotate an entry by hand.

The ~test/bench.sh~ script feeds the same log non-interactively:

#+begin_src sh
test/bench.sh small [N]   # synthetic tree (default 10000 files)
test/bench.sh large       # Linux kernel v7.0 vs v6.19 (git clone on first run)
#+end_src

It records to ~BENCHMARKS.org~ by default.  Set ~EMELD_BENCH_SAME=1~ to also run and record the identical-files pass, ~EMELD_BENCH_RECORD=0~ to print without recording, or ~EMELD_BENCH_FILE=PATH~ to redirect the log.

* Per-Project Configuration with ~.dir-locals.el~

Emeld ships with Meld-style default filter groups (see above).  To override them per project, place a ~.dir-locals.el~ file above the left directory:

#+begin_src elisp
;;; .dir-locals.el
((nil
  . ((emeld-filter-groups . (("Backups" t "*~" "*.bak" "*.orig")
                            ("Hidden" nil ".*")
                            ("Logs" t "*.log" "logs/*")
                            ("Config" nil "*.cfg" "config/*"))))))
#+end_src

Toggle named groups on/off from the transient menu (~?~) or with ~M-x emeld-toggle-filter-group~.  The header line shows the current display state; review which groups are active and their globs with ~M-x emeld-list-filter-groups~ (~cl~ in the transient).
