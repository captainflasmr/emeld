#+TITLE: Emeld: Meld-Inspired Local Diff
#+AUTHOR: Antigravity

* Introduction

Emeld is a simple, side-by-side directory comparison tool for Emacs. It is designed to be a lightweight and maintainable alternative to other directory diff tools, with a focus on ease of use and a clean hierarchy.

* Features
- Side-by-side view in a single buffer.
- Recursive glob-based filtering (like Meld) — excluded at the ~diff~ level.
- ~.gitignore~ support, on by default — ignored files hidden on both sides, toggle with ~I~.  Turning it off shows a ~(!) gitignore off~ note in the header line, since including ignored files is the exception.
- Instant toggles for Same, New, and Modified (~S~/~N~/~M~).
- Each changed file carries a theme-independent status marker before its name — ~M~ modified, ~A~ left-only (new), ~D~ right-only (deleted) — shown on both sides of the row (including the struck-through name of a one-sided file); customize with ~emeld-status-markers~.
- Orphan files shown with strikethrough on the missing side (Meld-style, always on).
- Dired-style, per-side marking (~m~/~u~/~U~): the ~*~ sits in the column of the side you mark, and a node can be marked left, right, or both.  Copy/sync (~C~) makes the *other* side match the side you marked — a node marked on the side that has the file is copied across, while a node marked on its empty (struck-through) side is *deleted* from the other side, so you can resolve a one-sided file either way.  Bulk delete (~x~) deletes from every marked side; bulk-mark by status (~* m~ modified, ~* l~ left-only, ~* c~ the full left→right mirror set — modified + left-only + right-only).
- Filter groups toggleable from the transient menu.
- Content filters applied consistently to the scan, identical-file merge, inline/quick diffs and patch export: ignore whitespace (~i~ cycles off → amount → all), line endings (~v L~, CRLF vs LF), blank lines (~v B~), case (~v C~, directory mode only) and a regexp of lines to ignore (~v R~; git mode uses the subset ~git diff~ supports).
- Org-mode-style subtree cycling: ~TAB~ cycles the directory at point (FOLDED → DIRS → SUBTREE).  On a file, ~TAB~ instead peeks an inline diff underneath the row (Magit-style), expandable and collapsible without leaving the tree; the words that actually changed inside modified lines are highlighted like ~diff-refine-hunk~ (tune or disable with ~emeld-inline-diff-refine-max-spots~).  With the peek open, ~a~ applies the change block at point to the other file (~C-u a~ reverses the direction) — Meld-style block copying, undoable with ~u~.
- File copying between directories (~C~), via rsync when available — asynchronous and delta-efficient, with an optional exact-mirror (~--delete~) mode toggled with ~R~.
- Recursive ~diff~ buffers for the directory at point (~d~; at the top level this covers the whole root), and a non-intrusive preview (~=~/~SPC~) that diffs/opens the node at point while keeping point in the tree.
- Export changes as a unified-diff patch (~P~).
- Recent comparisons: every comparison is remembered, and the list persists across sessions so it can be re-run from ~M-x emeld-recent~ (or ~r~ in the transient Compare menu).
- Marked directories: flag a directory as comparison side A while browsing Dired (a plain command, no default key bindings), then compare it against the directory you are browsing.
- Side-aware navigation (~n~/~p~) and side-jumping (~o~).
- Change-oriented movement: ~M-n~/~M-p~ jump to the next/previous changed *file* (numeric prefix to repeat), skipping directory rows, identical files (when shown) and inline-diff preview lines; the header line shows how many changes are displayed.  ~j~ (~M-x emeld-jump-to-file~) jumps straight to a file by name — completion over every file the filters allow, status marker included — expanding folded folders on the way.
- Depth-limited "shallow" scan for huge trees or slow mounts (SMB/NFS): prefix ~emeld-diff~ with a depth (~C-u 2 M-x emeld-diff~) to scan only the top levels and stop; deeper directories are marked with a dim ~…~ and enumerated on demand by expanding them (~TAB~).
- Integration with ~ediff~.
- A treemacs-style file-tree sidebar (~M-x emeld-sidebar~) that follows and highlights the active file — built on the same tree machinery (see below).
- A tree-navigable, Dired-like file manager (~M-x emeld-dired~): mark, copy, rename, delete and create files in a single foldable tree instead of one flat listing (see below).
- Fully themeable (uses standard Emacs faces).

* Installation
Copy the files to your load path and add the following to your init file:
#+begin_src elisp
(add-to-list 'load-path "~/.emacs.d/offline-packages/local-packages/emeld")
(require 'emeld)
#+end_src

Emeld shells out to GNU ~diff~ (diffutils) for directory comparisons; ~git~ is needed only for revision comparisons, and ~rsync~, when available, is used for faster copying.

* Usage
Run ~M-x emeld-diff~ and select the two directories you wish to compare.
Alternatively, run ~M-x emeld-diff-dwim~ to automatically use open Dired buffers as the comparison sources.

For very large trees or slow filesystems (SMB/NFS), give ~emeld-diff~ a prefix argument to limit the initial scan depth — e.g. ~C-u 2 M-x emeld-diff~ scans two directory levels, ~C-u M-x emeld-diff~ just one.  The scan stops there and shows the tree; directories below the limit (and one-sided directories) are marked with a dim ~…~.  Expand a marked directory (~TAB~) to scan its subtree in place, and plain ~G~ re-runs the bounded scan at the same depth.  The header-line shows ~[depth N]~ while a depth limit is in effect.

** Comparing a marked directory with the current one

Rather than opening two Dired windows or typing both paths, mark one directory as side A and compare it against the directory you are browsing:

- ~M-x emeld-mark-dir-a~ marks the current directory (in Dired, the Dired buffer's directory) as side A.  The mark is global state, not tied to a particular buffer.
- ~M-x emeld-compare-marked-dirs~ compares side A against the current buffer's directory (in Dired, the Dired buffer's directory).  It errors if nothing is marked, if either directory no longer exists, or if the two resolve to the same directory.
- Re-marking side A replaces the mark, so reversing a comparison is just marking the other directory and comparing again (or pressing ~W~ to swap the panes while viewing).

The commands are plain functions with no default key bindings — bind the ones you use, e.g.:

#+begin_src elisp
(global-set-key (kbd "C-c z a") #'emeld-mark-dir-a)
(global-set-key (kbd "C-c z c") #'emeld-compare-marked-dirs)
#+end_src

So the flow is: press your A key in the first Dired buffer, navigate to the second directory, then compare.  The mark is global state, not tied to a particular buffer, and the pair flows through ~emeld-diff~ — so it is recorded in ~emeld-recent~ and can be re-run from there.

** Comparing git revisions

From inside a git work tree, run ~M-x emeld-git-diff~ (or ~G~ in the transient menu — Version Control → git revisions) to compare two revisions instead of two directories.  You are prompted for a left (old) and right (new) revision; completion offers branches, tags and recent commits, plus ~[working tree]~ and ~[index]~.  The default compares ~HEAD~ against the working tree, i.e. "what have I changed since the last commit".

The result is the same side-by-side tree, showing the hierarchy of added, deleted and modified files between the two revisions (renames appear as a deleted old path plus an added new path).  Because the content lives in git history rather than on disk:

- ~RET~ / ~f~ opens a file at its revision (via ~git show~; the working-tree side opens the real file), ~e~ Ediffs the two revisions, ~=~ / ~SPC~ / ~d~ show a ~git diff~, and ~TAB~ peeks an inline diff of a file underneath its row.
- ~S~ (show Same) lists the left revision and merges in every unchanged file.
- A foldable commit-context block sits between the revision header and the tree, in two columns aligned to the panes (left/old commit under the left header, right/new under the right): each shows its short SHA and subject, and ~c~ (or ~RET~ on the block) unfolds the author, date+time and full message.
- Header ~RET~ re-selects a revision for that side; ~W~ swaps the two revisions; ~G~ re-scans.
- Copy (~C~) and delete (~x~) are disabled — history cannot be written to.

The header line shows ~[git OLD→NEW]~ with the chosen revision labels; a revision that points at the current ~HEAD~ is shown as ~HEAD (SHA)~.

*** Stepping through history

~M-x emeld-git-step-history~ (or ~H~ in the transient — Version Control → git history step) walks the history one commit at a time.  You pick a starting revision (default ~HEAD~); the buffer shows what that commit changed — its first parent on the left, the commit on the right — and you step through:

- ~,~ — move to the *older* commit (back in time)
- ~.~ — move to the *newer* commit (forward, back toward the start)

Each step re-scans and updates the commit-context block, so you can quickly skim what changed in successive commits.  The root commit is compared against the empty tree (labelled ~∅ (root)~), and the header line shows ~[hist i/N]~.  When the newest commit is ~HEAD~, pressing ~.~ once more steps all the way to the *working tree* — the newest commit on the left, your uncommitted changes on the right (header line ~[hist WT/N]~) — so a single walk runs from any point in history right up to what you have not yet committed.  Only the first-parent chain is followed, up to ~emeld-git-history-limit~ commits (default 1000).  Pressing ~,~/~.~ in any git comparison where the right side is a commit starts a walk anchored there.

* File-Tree Sidebar (treemacs-style)

~M-x emeld-sidebar~ docks a dedicated side window showing a single directory tree — not a diff — built with the same tree machinery as the comparison view.  It roots at the current file's project (git toplevel, then ~project.el~, then the file's own directory; a prefix arg ~C-u M-x emeld-sidebar~ prompts for the root), and run again it closes the window.

Children load lazily as you open directories.  Dotfiles are hidden by default (toggle with ~h~), and filter groups that are active by default (e.g. version-control noise) are honoured.  Because the side window is narrow, the sidebar opens in the most condensed (~extreme~) tree density; cycle it with ~z~ and toggle the tree-line guides with ~T~ — both kept local to the sidebar.

The active file is revealed — its ancestor directories expanded — and highlighted; with ~emeld-sidebar-follow-mode~ (a global minor mode, enabled alongside the sidebar when ~emeld-sidebar-follow~ is non-nil) it keeps up automatically as you switch buffers.

| Key       | Action                                          |
|-----------+-------------------------------------------------|
| RET / f / v | Open file in the main window (or toggle a dir) |
| TAB       | Expand / collapse the directory at point        |
| o         | Open file without leaving the sidebar           |
| n / p     | Next / previous line                            |
| g         | Refresh from disk (keeps expansion and point)   |
| [         | Collapse all                                    |
| ]         | Expand all (loads the whole tree from disk)     |
| <backtab> | Cycle visibility (top → folder skeleton → all)  |
| .         | Reveal the main window's file                   |
| h         | Toggle hidden (dot) files                       |
| z         | Cycle tree density (compact → extreme → wide)   |
| T         | Toggle tree-line guides                          |

| q         | Close the sidebar                               |

Customize ~emeld-sidebar-position~ (~left~/~right~), ~emeld-sidebar-width~, ~emeld-sidebar-show-hidden~ and ~emeld-sidebar-follow~.

* Tree-navigable Dired (~M-x emeld-dired~)

~M-x emeld-dired~ shows a directory as a single foldable *tree* you can operate on like Dired — mark files, copy, rename, delete and create files and directories — instead of one flat listing.  It is built with the same tree machinery as the comparison view and the sidebar, but is a stand-alone file manager: it takes over its window like Dired (rather than docking like ~emeld-sidebar~) and is mark/operation oriented rather than following the active file.

Invoked from a Dired buffer it roots at that buffer's directory; elsewhere it roots at ~default-directory~.  A prefix arg (~C-u M-x emeld-dired~), or ~M-x emeld-dired-find~, prompts for the directory.  ~^~ re-roots at the parent directory.

Marking is Dired-style and single-column: ~m~ marks (~*~), ~d~ flags for deletion (~D~).  Operations act on the marked files, or — when nothing is marked — on the file at point, exactly like Dired.  Dotfiles are shown by default (toggle with ~h~); children load lazily as you open directories, and the header line shows live marked/flagged counts.  Every operation rebuilds the tree in place, preserving expansion and point.

| Key       | Action                                                     |
|-----------+------------------------------------------------------------|
| RET / f   | Visit the file at point (or toggle a directory)            |
| o         | Visit the file in another window                           |
| TAB       | Expand / collapse the directory at point                   |
| n / p     | Next / previous line                                       |
| ^         | Re-root at the parent directory                            |
| [ / ]     | Collapse all / expand all                                  |
| m         | Mark the file at point (~*~)                                |
| d         | Flag the file at point for deletion (~D~)                   |
| u / DEL   | Unmark (forward / backward)                                |
| U         | Unmark all                                                 |
| t         | Toggle marks on all visible files                          |
| x         | Delete the flagged (~D~) files                              |
| D         | Delete the marked files (or file at point)                 |
| C         | Copy the marked files (or file at point)                   |
| R         | Rename / move the marked files (or file at point)          |
| +         | Create a directory                                         |
| M-+       | Create a file (and visit it)                               |
| g         | Refresh from disk (keeps expansion and point)              |
| h         | Toggle hidden (dot) files                                  |
| z         | Cycle tree density (compact → extreme → wide)              |
| T         | Toggle tree-line guides                                    |
| q         | Quit                                                       |

Deletions move the files to trash rather than erasing them outright.  When several files are marked, ~C~ and ~R~ require the destination to be an existing directory.  Customize ~emeld-dired-show-hidden~ (default ~t~) to show or hide dotfiles by default.

* Transient Menu (~?~)

Magit-style: the top level has three rows — a ~Transient commands~ group with the eight sub-menu entry points, a ~Show~ | ~Navigate~ row pairing the file-kind toggles with change-oriented movement, and an ~Essential commands~ group for the most-used direct actions.  The group keys (~d~ ~T~ ~h~ ~s~ ~F~ ~v~ ~r~ ~O~) also work directly from the tree — pressing one opens its sub-menu without going through ~?~ first.  Pressing ~q~ (or ~C-g~) inside a sub-menu returns to the top level.

Top-level row 2 is ~Show~ | ~Navigate~ :: toggle file kinds — same (~S~), new (~N~), modified (~M~) — beside change movement — next change (~M-n~), previous change (~M-p~), jump to file (~j~).

Top-level row 3 is ~Essential commands~ :: copy (~C~), mark (~m~), hop tree (~o~), ediff (~e~), rescan (~G~), undo (~u~).

- ~Compare~ (~d~) :: Start or re-scan.  ~d~ compare two directories, ~r~ reopen a recent comparison, ~g~/~G~ rescan, ~k~ stop scan.
- ~Git~ (~T~) :: ~G~ git revisions, ~H~ step git history (`,` older / `.` newer).
- ~Act — Sync~ (~s~) :: ~C~ copy/sync marked/at point (its label names the copy method in effect — ~rsync~ or ~built-in copy~), ~a~ apply the change block at point to the other file (~C-u a~ reverses; needs an open peek), ~R~ toggle mirror copy, ~x~ delete marked/at point, ~D~ delete at point (this pane), ~u~ undo last delete/copy/change block, ~l~ list undoable operations.
- ~Act — Diff~ (~h~) :: ~d~ diff directory at point (whole root at the top level), ~P~ format patch.
- ~Act — Filter~ (~F~) :: Toggle filter groups on/off (~ca~, ~cb~, ... ~[x]~/~[ ]~ checkmarks), edit ~.dir-locals.el~ (~E~), or add the node at point as a filter (~&~).
- ~Inspect — View~ (~v~) :: Toggle what is displayed — tree-lines (~t~), tree density (~z~ cycles compact → extreme → wide), ~.gitignore~ respect (~I~), content filters — whitespace (~i~ cycles off → amount → all), line endings (~L~, CRLF vs LF), blank lines (~B~), case (~C~, directory mode only; ~git diff~ has no equivalent) and a regexp of ignorable lines (~R~ prompts, empty input clears) — commit message (~c~, git mode only), file size/mtime tags (~f~), session hide (~C-k~ hide node at point, ~C-u C-k~ unhides all); pane resize (~<~/~>~) and indent (~{~/~}~).
- ~Inspect — Mark~ (~r~) :: Mark/unmark the file on the current side (~m~/~u~); bulk-mark by status — modified (~* m~), left-only (~* l~), the full left→right mirror set (~* c~ — modified + left-only + right-only); ~U~ unmark all.
- ~Inspect — Open~ (~O~) :: ~e~ ediff, ~=~/~SPC~ preview without leaving the tree (soft diff a modified file, show a new/one-sided one, fold a directory), ~TAB~ peek inline diff, ~o~ hop to other tree; ~A~/~B~ jump to dired on the left/right side, ~w~ copy path.

Most commands keep a direct key binding in ~emeld-mode~ (see below); the sub-menu keys (~d~ ~T~ ~h~ ~s~ ~F~ ~v~ ~r~ ~O~) open their menu from the tree, and everything inside stays one more keystroke away (e.g. ~h d~ to diff a directory) — so the hierarchy stays discoverable without losing keyboard access.

* Customization

- ~emeld-filter-groups~: Named groups of globs toggleable from the transient menu.  Defaults:

  | Group           | Globs                                                                                                       |
  |-----------------+-------------------------------------------------------------------------------------------------------------|
  | Backups         | ~#*#~, ~.#*~, ~~*~, ~*~~, ~*.orig~, ~*.bak~, ~*.swp~                                                        |
  | OS metadata     | ~.DS_Store~, ~._*~, ~.Spotlight-V100~, ~.Trashes~, ~Thumbs.db~, ~Desktop.ini~                               |
  | Version Control | ~.git~, ~.svn~, ~.hg~, ~CVS~, ~_darcs~, ~.bzr~, ~_MTN~, ~.fslckout~, ~_FOSSIL_~, ~.fos~, ~.osc~             |
  | Binaries        | ~*.pyc~, ~*.a~, ~*.obj~, ~*.o~, ~*.so~, ~*.la~, ~*.lib~, ~*.dll~, ~*.exe~                                   |
  | Media           | ~*.jpg~, ~*.gif~, ~*.png~, ~*.bmp~, ~*.wav~, ~*.mp3~, ~*.ogg~, ~*.flac~, ~*.avi~, ~*.mpg~, ~*.xcf~, ~*.xpm~ |

- ~emeld-show-same~: Whether to show identical files (default nil).  When enabled, identical files appear in the tree.
- ~emeld-show-files~: Whether to show regular files (default t).  When disabled, only directories are displayed.
- ~emeld-same-files-method~: How toggling ~S~ finds identical files — ~list~ (default, fast: enumerate the left tree and subtract the files the initial scan already classified, avoiding a second content comparison) or ~diff~ (exact: re-run ~diff -rqs~).
- ~emeld-list-command~: Program + args used by the ~list~ method to enumerate files (default ~("find" "." "-type" "f")~; set to e.g. ~("fd" "--type" "f" "--hidden" "--no-ignore")~ to use fd).
- ~emeld-show-strikethrough~: Show strikethrough for orphan files on the missing side (default ~t~).  When nil, the missing side shows nothing.  The struck-through cell is also the marking target for deletion: with strikethrough on, marking it (~m~) marks the empty side, so ~C~ (sync) deletes the file from the side that has it.  With strikethrough off, marking a one-sided file snaps to the file side instead (so ~C~ copies it across).
- ~emeld-status-markers~: Alist of diff status → marker string shown before a file's name (default ~M~ modified, ~A~ left-only/new, ~D~ right-only/deleted; each includes a trailing space).  The marker appears on both sides of the row — including before the struck-through name of a one-sided file — and is drawn with the row's status face, so the status reads even under muted themes.  Add a ~same~ entry to mark identical files too (visible only with ~emeld-show-same~), or set a status to ~""~ to hide its marker.  Prefer symbols? ~≠ ~ / ~✚ ~ / ~✖ ~ work too.  Directories never get markers.
- ~emeld-ignore-whitespace~: How content comparison treats whitespace (default nil — compare exactly).  ~change~ ignores changes in the amount of whitespace (~diff -b~); ~all~ ignores whitespace entirely (~diff -w~).  Cycle with ~i~; applies to the scan, the identical-file merge, quick/inline diffs and (git mode) ~git diff~, and re-runs the comparison.  The header line shows ~[ws:amount]~ / ~[ws:all]~ while active.
- ~emeld-ignore-line-endings~: Ignore CRLF-vs-LF changes when comparing content (default nil).  Adds ~--strip-trailing-cr~ in directory mode and ~--ignore-cr-at-eol~ in git mode (Git 2.16+) to every diff invocation — including git's ~--name-status~ fast path, so both modes agree — and re-runs the comparison; toggle with ~v L~ (or ~M-x emeld-toggle-ignore-line-endings~) and the header shows ~[ignore-crlf]~.
- ~emeld-ignore-blank-lines~: Ignore blank-line changes when comparing content (default nil).  Adds ~--ignore-blank-lines~ to every diff invocation; toggle with ~v B~ (or ~M-x emeld-toggle-ignore-blank-lines~) and the header shows ~[ignore-blanks]~.  In git mode ~git diff --name-status~ can still list a file whose only change is blank lines when no other content filter is active; the scan re-verifies the modified files with one ~--numstat~ pass, so such a file is not listed either.
- ~emeld-ignore-case~: Ignore case in file *content* (default nil).  Directory mode only — ~git diff~ has no case-insensitive mode, so it is deliberately not applied to git revision comparisons; toggle with ~v C~ and the header shows ~[ignore-case]~.
- ~emeld-ignore-matching-lines~: Regexp of lines to ignore during content comparison (default nil).  A change is ignored when all of its changed lines match — e.g. ~"^#"~ skips comment-only edits.  Set it with ~v R~ or ~M-x emeld-set-ignore-matching-lines~ (empty input clears); the header shows ~[ignore-re]~.
- ~emeld-respect-gitignore~: Respect ~.gitignore~ rules during comparison (default ~t~).  Ignored files are hidden on both sides via a cached ~git ls-files~ query per root (honors nested ~.gitignore~, ~.git/info/exclude~, and the global excludes file).  Toggle interactively with ~I~; turning it off shows a ~(!) gitignore off~ note in the header line.  Requires the ~git~ executable; has no effect outside a work tree.
- ~emeld-tree-density~: How tightly the tree is indented (default ~wide~).  ~wide~ indents each level one space wider than the branch connector so a child's connector hangs one column past the parent's content (~│  └─file~), reading as hooking into the parent's subtree; ~compact~ matches the continuation indent to the branch width for a tighter tree (~│ └─file~) that sits well in the available space; ~extreme~ collapses each level to a single column regardless of ~emeld-indent-offset~ (~│└file~), for the densest tree — especially handy in the narrow ~emeld-sidebar~.  Files align with their sibling directories whatever the density.  Cycle compact → extreme → wide → compact with ~z~ (~emeld-cycle-tree-density~; in the sidebar, ~z~ runs ~emeld-sidebar-cycle-density~, which keeps the setting local to the sidebar).
- ~emeld-dir-prefix~: Prefix string shown before directory names (default ~""~, no prefix — chosen for compatibility with terminals and Windows builds that may not render emoji or icons).  Set to e.g. ~"📁 "~ for an icon, or any text marker you prefer.
- ~emeld-fold-collapsed-indicator~ / ~emeld-fold-expanded-indicator~: the fold toggle shown before a directory name, for the collapsed and expanded states (defaults ~"[+] "~ / ~"[-] "~, plain ASCII for terminal/Windows compatibility).  Set them to icons or triangles to mimic Meld; applies to both the diff view and ~emeld-sidebar~.  Keep the two the same display width so folded and unfolded names stay aligned.

  Some triangle recipes, roughly small → large:

  #+begin_src elisp
  ;; 1. Small triangles (treemacs-style)            U+25B8 / U+25BE
  (setq emeld-fold-collapsed-indicator "▸ "
        emeld-fold-expanded-indicator  "▾ ")

  ;; 2. Classic solid triangles — medium            U+25BA / U+25BC
  (setq emeld-fold-collapsed-indicator "► "
        emeld-fold-expanded-indicator  "▼ ")

  ;; 3. "Media" triangles — larger / bolder         U+23F5 / U+23F7
  (setq emeld-fold-collapsed-indicator "⏵ "
        emeld-fold-expanded-indicator  "⏷ ")

  ;; 4. Centred medium triangles                    U+2BC8 / U+2BC6
  (setq emeld-fold-collapsed-indicator "⯈ "
        emeld-fold-expanded-indicator  "⯆ ")
  #+end_src

  Because the indicator is inserted with its text properties intact, you can also scale *any* glyph up with a ~:height~ face (relative to your default font, so it tracks your font size; the glyph stays one column wide, so alignment is unaffected):

  #+begin_src elisp
  (setq emeld-fold-collapsed-indicator (propertize "▶ " 'face '(:height 1.4))
        emeld-fold-expanded-indicator  (propertize "▼ " 'face '(:height 1.4)))
  #+end_src

  Use single-width glyphs only — avoid emoji forms like ~▶️~/~🔽~ (often double-width and emoji-fonted, which throws off the column padding).  In a TTY with East-Asian "ambiguous = wide", glyphs like ~⏵~/~⏷~ may take two cells and shift alignment; the classic ~►~/~▼~ are the safest there.
- ~emeld-column-ratio~: Left pane width as percentage of window (default 50).
- ~emeld-show-file-meta~: Annotate file rows with dim size/mtime tags, e.g. ~(4.0K 06-19 22:53)~, on every side where the file exists (default nil; hidden for directories and in git-revision comparisons).  Toggle with ~M-x emeld-toggle-show-file-meta~ or ~f~ in the transient View menu.  The stats are computed once per file and cached on the node, so re-renders — expand/collapse, marks, other display toggles — do not re-stat the tree; turning the tags themselves on or off updates the rows on the next render.  A rescan (or a copy's re-classification) refreshes the stats, keeping the tags consistent with the tree's snapshot.
- ~emeld-inline-diff-refine-max-spots~: Word-level refinement cap for the inline diff peek (default 250).  The peek highlights the words that actually changed within modified lines, using the same machinery as ~diff-refine-hunk~; since each modified spot (a run of removed lines followed by a run of added lines) costs a small ~diff~ run, peeks with more spots than this are shown with plain ~diff-*~ faces to stay snappy.  Set to 0 to turn refinement off, or to ~nil~ to always refine.
- ~emeld-op-log-max~: Maximum undoable operations kept per comparison buffer (default 50).  Deletes and completed copies are logged with their trash/destination locations, and applied change blocks (~a~) with their old and new text; ~M-x emeld-undo-last-op~ (or ~u~ in the transient Sync menu) restores a deleted file from trash, removes a copied destination (to trash), or re-applies a change block's reverse edit.  A delete whose trash location cannot be captured is not logged and cannot be undone; files pruned by a mirror copy are never restorable; a change block whose applied text is no longer present refuses (keeping the entry for retry).  ~M-x emeld-list-operations~ (or ~l~ in the transient Sync menu) shows the stack newest-first; ~u~ (or ~RET~) on a line undoes that entry, each carrying its own safety checks so out-of-order undo is safe.
- ~emeld-scan-live-render~: Whether to redraw the tree progressively while a scan builds it (default nil).  Each redraw rebuilds the whole visible tree and, once started, blocks input until it finishes — the chief cause of jerkiness while a large comparison streams in.  By default emeld instead updates only the lightweight header-line progress bar during a scan and draws the finished tree once on completion, keeping Emacs fully responsive.  Set to ~t~ to watch the tree grow live (throttled by ~emeld-render-throttle~), at some cost to responsiveness on large repositories.
- ~emeld-render-throttle~: Minimum seconds between intermediate buffer redraws during a scan (default 0.15).  Only consulted when ~emeld-scan-live-render~ is non-nil; raise it to redraw less often on very large trees.  Intermediate redraws are also skipped whenever there is pending input, so an in-progress scan never blocks scrolling or typing; the final result is always rendered on completion.
- ~emeld-benchmark~: When non-nil, collect and report phased scan timings (default nil).  Both the initial scan and the identical-files (~S~) merge print a per-stage timing report to the echo area / ~*Messages*~.
- ~emeld-benchmark-file~: Org file where ~emeld-benchmark-record~ appends timing entries (default ~BENCHMARKS.org~ beside ~emeld.el~).
- ~emeld-copy-method~: How ~emeld-copy~ (~C~) transfers files — ~auto~ (default: use rsync when found on ~exec-path~, else the built-in copy), ~rsync~ (always rsync; error up front if missing), or ~builtin~ (always ~copy-file~ / ~copy-directory~).  rsync only sends the changed parts of a file, preserves metadata, and recurses efficiently, so it is faster and more robust for large or partly-synced trees.  Both paths run *asynchronously*, one node at a time, so Emacs stays responsive between nodes (a single very large node still blocks while it is copied); progress and the final tally show in the echo area, and the method in effect is named in the Sync menu, the confirmation prompt and the messages.  rsync output is logged to ~ *emeld-rsync*~.
- ~emeld-rsync-command~: Name or absolute path of the rsync executable (default ~"rsync"~).
- ~emeld-rsync-options~: Options passed to rsync, as a list of strings (default ~("-a")~).  ~-a~ preserves permissions, timestamps and symlinks and recurses; add e.g. ~"-z"~ for compression.  ~--delete~ is controlled separately by ~emeld-copy-mirror~, not by this list.
- ~emeld-copy-mirror~: When non-nil, rsync directory copies are exact mirrors via ~--delete~ (default nil) — the destination directory is made to match the source exactly, removing files present only on the destination, so "copy left→right" becomes a true mirror rather than a merge.  Only affects rsync copies of directories (single files and the built-in copy are unaffected, since ~--delete~ has nothing to prune for one file and ~copy-directory~ cannot delete).  To mirror a whole tree, copy a directory node (e.g. a left-only directory) with this enabled.  ~emeld-copy~ labels the action "Mirror" and warns before proceeding.  Toggle it interactively with ~R~ (~emeld-toggle-mirror~); while on, the header line shows ~[Mirror]~.
- ~emeld-recent-max~: Maximum number of comparisons kept in ~emeld-recent~ (default 20).
- ~emeld-recent-file~: File where the recent-comparison list is persisted between sessions (default ~emeld-recent.eld~ in ~user-emacs-directory~).

* Recent Comparisons

There is nothing to save explicitly: every comparison — directory pair, git-revision comparison, or history walk — is recorded automatically in ~emeld-recent~ (newest first, deduplicated, capped by ~emeld-recent-max~).  ~M-x emeld-recent~ (or ~r~ in the transient Compare menu) reopens one via completion, skipping and pruning entries whose directories are gone.

The list persists across sessions in ~emeld-recent-file~ (default ~emeld-recent.eld~ in ~user-emacs-directory~): it is written whenever a comparison is recorded and read back when emeld loads, so neither ~savehist-mode~ nor any other setup is required.  Delete the file to forget all recent comparisons.

* Benchmarking and Regression Tracking

To keep a record of large-repo comparison timings across builds:

1. Enable timing collection: ~(setq emeld-benchmark t)~.
2. Run one or more comparisons (the initial scan, and toggle ~S~ for the identical-files pass).  Each completed scan prints a report and is queued in memory.
3. ~M-x emeld-benchmark-record~ writes all queued runs to ~emeld-benchmark-file~ under a single dated heading, stamped with the machine specs and emeld git revision, then clears the queue.

Because every entry records the host, CPU, RAM, Emacs version and emeld build, the resulting ~BENCHMARKS.org~ lets you compare runs across commits and machines to spot performance regressions.  ~M-x emeld-benchmark-system-info~ inserts the current machine's specs at point if you want to annotate an entry by hand.

The ~test/bench.sh~ script feeds the same log non-interactively:

#+begin_src sh
test/bench.sh small [N]   # synthetic tree (default 10000 files)
test/bench.sh large       # Linux kernel v7.0 vs v6.19 (git clone on first run)
#+end_src

It records to ~BENCHMARKS.org~ by default.  Set ~EMELD_BENCH_SAME=1~ to also run and record the identical-files pass, ~EMELD_BENCH_RECORD=0~ to print without recording, or ~EMELD_BENCH_FILE=PATH~ to redirect the log.

* Per-Project Configuration with ~.dir-locals.el~

Emeld ships with Meld-style default filter groups (see above).  Starting a comparison creates a ~.dir-locals.el~ at the left directory with those defaults when none exists yet, so there is always a populated file to jump to (~e~) — an existing file is never touched.  To override the defaults per project, edit that file:

#+begin_src elisp
;;; .dir-locals.el
((nil
  . ((emeld-filter-groups . (("Backups" t "*~" "*.bak" "*.orig")
                            ("Hidden" nil ".*")
                            ("Logs" t "*.log" "logs/*")
                            ("Config" nil "*.cfg" "config/*"))))))
#+end_src

Toggle named groups on/off from the transient menu (~?~ then ~F~) or with ~M-x emeld-toggle-filter-group~.  The header line shows the current display state; review or hand-edit the groups and their globs in ~.dir-locals.el~ with ~M-x emeld-edit-dir-locals~ (~E~), then rescan (~G~) to apply.

You do not have to write ~.dir-locals.el~ by hand.  With point on a file or directory in the tree, ~&~ (~emeld-add-filter-at-point~, also under ~&~ in the transient Filter sub-menu) adds it as a filter and saves it: it prompts for the glob (defaulting to the basename — edit it to e.g. ~*.log~ or a ~sub/dir~ relative path) and the group to add it to (completing over existing names; a new name creates a new, active group), writes the updated ~emeld-filter-groups~ to ~.dir-locals.el~ at the left root, activates the group and rescans so the matching files drop out at once.  Repeat it to progressively tidy up a fresh comparison; the exclusions persist for next time.

For a *temporary* tidy-up that you do not want recorded, ~C-k~ (~emeld-hide-at-point~) hides just the node at point — and, for a directory, its subtree — for this session only.  Nothing is written to ~.dir-locals.el~, and the hide survives a rescan within the session; the header line shows a ~(!) N hidden~ note while anything is tucked away.  Restore everything with ~C-u C-k~ (~emeld-unhide-all~).  Use this when you want to declutter the view but stay interested in the item later; use ~&~ when the exclusion should be permanent.
